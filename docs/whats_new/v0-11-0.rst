v0.11.0 - Rankine's Renaissance (July, 26, 2026)
++++++++++++++++++++++++++++++++++++++++++++++++

The solver was restructured from the ground up for this release. The new
:ref:`solver section <modules_solver_label>` in the documentation describes
the full solution process. This page lists the changes relevant for updating
existing models and custom components.

API Changes
###########
- Everything deprecated with a :code:`FutureWarning` in this release will be
  removed or changed in version 0.12; each warning names its replacement.
- The solver state of the :py:class:`~tespy.networks.network.Network` class
  has moved to the new :py:class:`~tespy.solver.problem.Problem` class. A
  fresh instance is created with every call of
  :py:meth:`~tespy.networks.network.Network.solve` and remains accessible
  through the new read-only :code:`Network.problem` property afterwards.
  Accessing solver attributes directly on the network, e.g.
  :code:`variables_dict`, :code:`residual`, :code:`jacobian`,
  :code:`increment`, :code:`residual_history`, :code:`lin_dep`,
  :code:`iter`, :code:`max_iter`, is deprecated and raises a
  :code:`FutureWarning`, use :code:`Network.problem.<name>` instead. The
  public inspection API, e.g.
  :py:meth:`~tespy.networks.network.Network.print_residuals`, and the
  :code:`status` and :code:`converged` attributes are unaffected.
- The convergence check operates on scaled residuals now: every residual
  is related to the response of its equation, every increment to the
  magnitude of its variable, which makes the acceptance independent of
  the physical scale of the plant. :code:`residual_history` and the
  residual column of the iteration information display the largest scaled
  residual instead of the norm of the raw residual vector,
  :py:meth:`~tespy.networks.network.Network.print_residuals` shows both.
  See the :ref:`solving section <networks_solving_label>`.
- The starting value generation was reworked, see the
  :ref:`starting values section <solver_starting_values_label>` for the
  new process. Custom components may need updates in the hooks that
  contribute starting value information:

  - :code:`initialise_source` and :code:`initialise_target` are only
    consulted as a last fallback for a generic **pressure** value anymore.
    Their enthalpy branches are never called; starting enthalpies are
    generated by the automatic machinery instead.
  - Components can override
    :py:meth:`~tespy.components.component.Component._initial_affine_edges`
    (approximate pressure and enthalpy relations between the ports, used
    to propagate known values through the network),
    :py:meth:`~tespy.components.component.Component._initial_temperature_edges`
    (approximate temperature relations, reconciled into one starting
    temperature per connection) and
    :py:meth:`~tespy.components.component.Component.initial_state`
    (expected phase at a port, turned into saturation pressure anchors
    and phase consistent enthalpies). The base class defaults cover
    components with a single inlet and a single outlet.
- The dependency declarations of equations are load-bearing for the new
  block decomposition: an incomplete declaration of a custom equation can
  render the problem structurally singular for block-wise solving. The
  error message points to :code:`nw.solve(mode, block_solve=False)` for
  that case.
- The :code:`power_connector_location` parameter of
  :py:class:`~tespy.components.heat_exchangers.simple.SimpleHeatExchanger`
  (and its subclasses) has been removed. It was deprecated and without
  effect. Loading a network export containing removed component
  parameters does not fail anymore: unknown parameters are skipped with a
  warning, so files from older versions stay loadable.

New Features
############
- The equation system is solved block-wise by default: a Dulmage-Mendelsohn
  decomposition brings it into block lower triangular form and the blocks are
  solved in precedence order. Failures escalate in stages up to the
  simultaneous solution of the full system from its initial state, which
  reproduces the behavior of previous versions exactly - the block phase can
  therefore never degrade robustness. The simultaneous solution can be enforced
  with :code:`nw.solve(mode, block_solve=False)`. See the
  :ref:`decomposition <solver_decomposition_label>` and
  :ref:`solving <networks_solving_label>` sections.
- Under- and over-determination errors and structural singularities name the
  specific equations and variables of the defective part of the model,
  interactively available through
  :py:meth:`~tespy.networks.network.Network.print_structural_analysis`.
- The solution process can be staged:
  :py:meth:`~tespy.networks.network.Network.presolve` prepares the problem and
  stops before solving, so variables can be inspected and modified,
  :py:meth:`~tespy.networks.network.Network.solve_continue`
  then runs the solver. With
  :code:`nw.solve(mode, pause_on_block_failure=True)` the solver pauses at the
  first failing block (:code:`status` 20) for interactive debugging of that
  exact state. See the section on
  :ref:`interacting with the solver <solver_interaction_label>`.
- Starting values can be provided as temperature and vapor quality guesses
  now, e.g. :code:`conn.set_attr(T0=75, x0=0.5)`: the temperature guess
  anchors the starting temperature estimation and both are converted into
  enthalpy and saturation pressure starting values. The guesses override
  values of a previous solution and are consumed by a successful solve
  (`#622 <https://github.com/oemof/tespy/issues/622>`__).
- New inspection methods report the mathematical structure of the
  problem: the variable space reduction and the provenance of presolved
  values (:py:meth:`~tespy.networks.network.Network.print_presolved_variables`),
  the block decomposition
  (:py:meth:`~tespy.networks.network.Network.print_blocks`,
  :py:meth:`~tespy.networks.network.Network.print_incidence_matrix` with
  :code:`block_order=True`) and the state of a failed block
  (:py:meth:`~tespy.networks.network.Network.print_block_jacobian`,
  :py:meth:`~tespy.networks.network.Network.print_block_states`). See the
  :ref:`problem reduction section <solver_reduction_label>`.

Bug Fixes
#########
- The residual of the :math:`\zeta/D^4` pressure loss equation saturated with
  vanishing derivatives when the pressure difference approached zero or the
  mass flow diverged. It is now formulated in terms of the pressure difference,
  which keeps gradient information exactly where the equation was most violated
  and removes the special case branch for zero mass flow.
- Enthalpy starting values inside the two phase dome could fail with a linear
  dependency when a temperature equation sat on the residual plateau of the two
  phase region. The all-zero jacobian row recovery and its bracketing search
  handle these plateaus now, e.g. the SEGS model converges without its previous
  two stage initialization.
- Exporting a network before solving it serialized plain numeric specifications
  with the global default units instead of the network's default units, e.g. a
  temperature of 200 set under :code:`°C` defaults was exported as
  :code:`200 kelvin` and misread on import. Solved networks were not affected.
- :py:meth:`~tespy.networks.network.Network.set_attr` now actually emits
  its :code:`FutureWarning`: the deprecation notice existed but was never
  raised.
- Solver runs are bit-exact reproducible now. Two defects injected run to
  run varying floating point noise into the Jacobian: the numeric
  derivatives restored the perturbed value by arithmetic (leaving one ulp
  sized residues that depended on the evaluation order) and the evaluation
  order itself followed the per process iteration order of sets. Marginal
  models could converge in one run and fail in the next; results and
  iteration counts are now identical across repeated runs.
- The postprocessing limit checks are noise aware now: a parameter value
  beyond its declared bound by less than a relative tolerance - related to
  the magnitude of the parameter itself or of a declared reference
  parameter, e.g. the thermal input for the heat dissipation of a
  combustion chamber - is snapped onto the bound instead of being
  reported. Converged solutions are no longer flagged with
  :code:`status = 1` for numerical noise on exact bounds.
- Value ranges (:code:`m_range`, :code:`p_range`, :code:`h_range`) are
  exported in the network's default units now. Files exported with earlier
  versions hold raw SI magnitudes, which are reinterpreted in the default
  units on load - check or re-export old files carrying range
  specifications.

Other Changes
#############
- The solver detects when the residual alternates between two values and
  activates the oscillation damping automatically. The
  :code:`oscillation_damping` parameter of
  :py:meth:`~tespy.networks.network.Network.solve` remains available to
  activate it from the first iteration. See the
  :ref:`convergence stability section <module_convergence_label>`.
- Convergence acceptance was modified. A solution is only accepted in an
  iteration in which no convergence heuristic modified any value, replacing the
  fixed :code:`min_iter` floor. The default of :code:`min_iter` dropped from 4
  to 2 and warm started solves, e.g. in offdesign parameter sweeps, typically
  finish in two iterations.
- Debug logging was reworked throughout preprocessing and solving: it
  reports the fluid domains, the design/offdesign switch, the problem
  reduction and the block decomposition, and console output is no longer
  doubled when console logging is enabled.
- The construction of the mathematical problem moved from the network to
  :code:`Problem.build` and the affine elimination graph is a persistent
  :py:class:`~tespy.solver.structure.StructureGraph` instance, available
  as :code:`Network.problem.structure_graph`. The private network methods
  :code:`_build_graph`, :code:`_find_cycles_in_graph`,
  :code:`_raise_error_if_cycle` and
  :code:`_find_linear_dependent_variables` have been removed.
