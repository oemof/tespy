v0.11.1 - Rankine's Renaissance (August, 16, 2026)
++++++++++++++++++++++++++++++++++++++++++++++++++

New Features
############
- New :py:class:`~tespy.tools.helpers.UserDefinedVariable` class: a standalone
  solver variable that is not attached to any connection or component. It is
  referenced from the function and dependents of a
  :py:class:`~tespy.tools.helpers.UserDefinedEquation`, which closes the degree
  of freedom the variable adds. See the
  :ref:`user defined variables section <udv_label>` for an example
  (`PR #1034 <https://github.com/oemof/tespy/pull/1034>`__).
- The :py:class:`~tespy.components.heat_exchangers.sectioned.SectionedHeatExchanger`
  reports the required hot-side heat transfer area :code:`area_hot` as a result,
  in case :code:`area_ratio`, :code:`R_cond` and the alpha values of all phases
  occurring in the solution are set
  (`PR #1035 <https://github.com/oemof/tespy/pull/1035>`__).
- Presolving logs every determination: which specification (or previously
  presolved value) eliminates which variables, both as solver debug messages
  and as a structured record. :code:`Network.get_presolve_log` returns the
  records in order of occurrence, with the originating specifications of each
  determination resolved transitively
  (`PR #1040 <https://github.com/oemof/tespy/pull/1040>`__).
- New :py:class:`~tespy.components.heat_exchangers.ntu.NTUHeatExchanger`
  component: the heat transfer coefficient :code:`UA` is linked to the heat
  transferred through the effectiveness-NTU relation of a specifiable
  :code:`flow_arrangement` (counterflow, parallelflow, crossflow with any
  mixing combination and shell and tube with an arbitrary number of shell
  passes). :code:`eps`, :code:`NTU` and the capacity rate ratio :code:`C_r`
  are reported as results
  (`PR #1045 <https://github.com/oemof/tespy/pull/1045>`__).
- The specifications of a network can be saved, cleared and restored with the
  new methods :py:meth:`~tespy.networks.network.Network.save_specifications`,
  :py:meth:`~tespy.networks.network.Network.clear_specifications` and
  :py:meth:`~tespy.networks.network.Network.restore_specifications`. This
  allows switching between different parametrizations of a topologically
  unchanged network
  (`PR #1047 <https://github.com/oemof/tespy/pull/1047>`__).
- The cycle diagram handling of the
  :py:class:`~tespy.models.template.ModelTemplate` class can be customized now
  (`PR #1046 <https://github.com/oemof/tespy/pull/1046>`__):

  - The new :py:meth:`~tespy.models.template.ModelTemplate.create_diagram`
    method is a public hook for diagram creation. Override it to adjust e.g.
    the isoline ranges to the operating envelope of your model.
  - Pre-configured diagrams can be registered per fluid with
    :py:meth:`~tespy.models.template.ModelTemplate.register_diagram` or passed
    directly to the plotting methods via the new :code:`diagram` keyword,
    which is especially useful in interactive sessions.
  - Fluids not supported by fluprodia (mixtures, incompressibles or fluids
    outside the default isoline range) no longer raise an error in the plotting
    methods. Instead a warning is logged and the plot falls back to showing the
    state points only. An is raised if :code:`strict=True` is passed to the
    respective method.

- The :code:`delta` of a :py:class:`~tespy.connections.connection.Ref` can be
  specified as :code:`pint.Quantity` as well
  (`PR #1051 <https://github.com/oemof/tespy/pull/1051>`__).
- Connections, components and their data containers provide readable
  :code:`repr` and :code:`print` output now, which can be controlled globally
  with :code:`tespy.set_display_mode`:

  - :code:`"compact"` (default)
  - :code:`"extensive"`
  - :code:`"none"`

  See the :ref:`general configuration <general_configuration_label>` section
  for an example (`PR #1052 <https://github.com/oemof/tespy/pull/1052>`__).
- A :py:class:`~tespy.networks.network.Network` can be converted into a
  :py:class:`~tespy.components.subsystem.Subsystem` with the new
  :py:meth:`~tespy.components.subsystem.Subsystem.from_network` method. The
  boundary components of the `Network` instance, e.g. :code:`Source` and
  :code:`Sink`, are automatically by the `SubsystemInterface` to allow
  embedding the subsystem into another network. The :code:`keep` parameter
  controls which state is carried into the subsystem instance
  (`PR #1021 <https://github.com/oemof/tespy/pull/1021>`__):

  - full parametrization (:code:`"specifications"`, default),
  - starting values only (:code:`"starting_values"`)
  - nothing (:code:`"nothing"`)

Bug Fixes
#########
- The enthalpy to temperature inversion of the
  :py:class:`~tespy.tools.fluid_properties.wrappers.IncompressibleFluidWrapper`
  returned wrong temperatures for (nearly) constant heat capacity data. The
  quadratic formula is now evaluated in its numerically stable form.
- The section result arrays of the
  :py:class:`~tespy.components.heat_exchangers.parallel.ParallelFlowHeatExchanger`
  (:code:`T_hot_sections`, :code:`T_cold_sections`, :code:`Q_sections`,
  :code:`lmtd_per_section`) paired the temperature profiles in counterflow
  orientation. Both profiles now run from the common inlet end (maximum
  temperature difference at zero heat transferred) to the common outlet end,
  aligned on the cumulative heat axis of the parallel flow configuration
  (`PR #1043 <https://github.com/oemof/tespy/pull/1043>`__).
- After solving and a difference in results between the specified input and the
  calculated property, the component results tables were not updated while the
  connection results tables were. Both now report the state of the latest solve
  (`PR #1051 <https://github.com/oemof/tespy/pull/1051>`__).
- The :code:`delta` of a referenced property specification was reinterpreted in
  the current default units at every solve. Changing the default units between
  two solves silently changed its value
  (`PR #1051 <https://github.com/oemof/tespy/pull/1051>`__).

Other Changes
#############
- Changing the default units through
  :py:meth:`~tespy.tools.units.Units.set_defaults` after a network has been
  solved is now well defined and warns about its consequences:

  - Values specified as plain numbers and results are converted from their SI
    value to the updated default units from the next solve on.
  - New plain number specifications are interpreted in the new default units.
  - Values specified as :code:`pint.Quantity` keep their unit.

  Previously, already converted values silently kept their old unit while
  re-specified values picked up the new one, mixing unit systems within a
  single network (`PR #1051 <https://github.com/oemof/tespy/pull/1051>`__).
- Support for importing networks exported with tespy v0.8 or earlier through
  :py:meth:`~tespy.networks.network.Network.from_json` has been removed. The
  same applies to design and initialisation state files written with tespy v0.9
  or earlier. To migrate such files, load and re-save them with an intermediate
  tespy version, e.g. v0.10.0
  (`PR #1021 <https://github.com/oemof/tespy/pull/1021>`__).
- The determination error and debug messages on the problem reduction report
  the number of directly specified variables, so the difference between the
  original and the reduced problem size becomes traceable
  (`PR #1034 <https://github.com/oemof/tespy/pull/1034>`__).
- Adding a connection or component, which is already part of a different
  network, now raises an error. To use the same model in a second network,
  create an independent copy of it, e.g. with
  :py:meth:`~tespy.networks.network.Network.export` and
  :py:meth:`~tespy.networks.network.Network.from_json`
  (`PR #1021 <https://github.com/oemof/tespy/pull/1021>`__).
- The postprocessing overhead per solve has been reduced
  (`PR #1051 <https://github.com/oemof/tespy/pull/1051>`__):

  - Unit strings are parsed into pint objects only once per unit and registry
    instead of once per converted value.
  - The results DataFrames are built lazily on first access of
    :code:`Network.results`.

Documentation
#############
- New advanced tutorial on a CO2 transcritical booster refrigeration system of
  the kind used in supermarkets. The model is implemented on top of the
  :py:class:`~tespy.models.template.ModelTemplate` class and demonstrates
  log(p)-h and QT diagram plotting, a sensitivity analysis of the gas cooler
  pressure and the optimization of the COP with pymoo. See the
  :ref:`tutorial <tutorial_co2_refrigeration_label>` for details.
