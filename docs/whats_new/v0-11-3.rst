v0.11.3 - Rankine's Renaissance (October, 15, 2026)
+++++++++++++++++++++++++++++++++++++++++++++++++++

New Features
############
- A new wrapper class for
  `thermopack <https://github.com/thermotools/thermopack>`__ is available, i.e.
  the
  :py:class:`~tespy.tools.fluid_properties.wrappers.thermopack.ThermopackWrapper`.
  It provides cubic, SAFT, CPA and multiparameter equations of state with fast
  and robust flash routines, which makes it especially interesting for modeling
  zeotropic mixtures without a REFPROP license. Install it with
  :code:`uv add thermopack` or :code:`pip install thermopack`. The
  :ref:`fluid properties documentation <thermopack_wrapper_label>` shows how to
  use it (`PR #1067 <https://github.com/oemof/tespy/pull/1067>`__).
- New :py:class:`~tespy.components.nodes.equilibrium_separator.EquilibriumSeparator`
  component: a phase separator that also handles single phase inlet states
  (`PR #1036 <https://github.com/oemof/tespy/pull/1036>`__).
- A Newton iteration that fails returns to the state with the lowest scaled
  residual and continues with a backtracking line search instead. Converging
  calculations are not affected. The behavior is controlled by the new
  :code:`line_search` argument of
  :py:meth:`~tespy.networks.network.Network.solve`: :code:`"stagnation"`
  (default), :code:`"always"` or :code:`"off"`
  (`PR #1094 <https://github.com/oemof/tespy/pull/1094>`__).

Bug Fixes
#########
- Result-only properties now reject user specifications with a
  :code:`TypeError`, instead of accepting inputs that have no corresponding
  equation. This includes heat exchanger :code:`lmtd`, connection :code:`s`
  and :code:`vol`, and other calculated component and humid-air outputs.
  Starting values for these connection properties are also rejected.
  Calculated results and network imports remain available
  (`issue #1070 <https://github.com/oemof/tespy/issues/1070>`__).
- In case the outlet state was near saturated state, the Baumann rule equation
  of :py:class:`~tespy.components.turbomachinery.steam_turbine.SteamTurbine`
  sometimes crashed in the :code:`brentq` root search. The equation now assumes
  dry expansion in such cases
  (`PR #1065 <https://github.com/oemof/tespy/pull/1065>`__).
- Connections of components with ten or more ports of one type were sorted by
  the port id string, e.g. :code:`inl[1]` referred to :code:`in10` instead of
  :code:`in2`. They are now sorted in the order of the port declaration
  (`PR #1085 <https://github.com/oemof/tespy/pull/1085>`__).
- Deprecated parameter names of a parent class were lost if a subclass defined
  own aliases, e.g. :code:`kA` on the
  :py:class:`~tespy.components.heat_exchangers.sectioned.SectionedHeatExchanger`.
  Also, the deprecated parameter was set and exported alongside its
  replacement (`PR #1085 <https://github.com/oemof/tespy/pull/1085>`__).
- A warning is logged if fixed mass fractions of a fluid branch do not sum up
  to 1 and no fluid is left to fill the remainder
  (`PR #1085 <https://github.com/oemof/tespy/pull/1085>`__).
- The derivative of the :code:`fluid_balance` equation was wrong, which could
  prevent convergence of models with variable fluid composition
  (`PR #1086 <https://github.com/oemof/tespy/pull/1086>`__).
- The :py:class:`~tespy.components.nodes.merge.Merge` applied an arbitrary
  subset of the species balances if the composition at the outlet was partially
  specified, so results could differ between python processes. The balances of
  the variable fractions are applied now
  (`PR #1086 <https://github.com/oemof/tespy/pull/1086>`__).
- A :py:class:`~tespy.components.nodes.node.Node` closing a recirculation loop
  caused infinite recursion in the fluid propagation
  (`PR #1086 <https://github.com/oemof/tespy/pull/1086>`__).
- The equal temperature equation of the
  :py:class:`~tespy.components.nodes.separator.Separator` crashed if an
  outlet enthalpy was determined by presolving, and its derivative ignored the
  outlet composition
  (`PR #1086 <https://github.com/oemof/tespy/pull/1086>`__).
- Unspecified properties were exported with the SI unit, which pinned the unit
  on import, e.g. the results of a
  :py:class:`~tespy.components.subsystem.Subsystem` created from an exported
  network were reported in SI units instead of the units of the network. The
  unit in a file describes the stored value only, imported values are reported
  in the default units of the network they are loaded into
  (`PR #1089 <https://github.com/oemof/tespy/pull/1089>`__).
- The relative humidity :code:`r` of an
  :py:class:`~tespy.connections.humidairconnection.HAConnection` is constant
  above saturation. Starting values and iterates above saturation are now
  projected onto the specified relative humidity, which previously caused
  singular Jacobians. Also, the equation used a stale temperature if :code:`T`
  was not specified
  (`PR #1086 <https://github.com/oemof/tespy/pull/1086>`__).
- :py:class:`~tespy.connections.powerconnection.PowerConnection` and
  :py:class:`~tespy.connections.heatconnection.HeatConnection` accept a
  :py:class:`~tespy.components.subsystem.Subsystem` as source or target, and
  :code:`print_results(subsystem=...)` works with mixed connection types
  (`PR #1092 <https://github.com/oemof/tespy/pull/1092>`__).
- CoolProp 8.1 raises an error for the viscosity of two-phase states, which
  crashed the :code:`darcy_group` pressure drop equation whenever an iterate of
  the inlet or the outlet was inside the two-phase region, e.g. for a saturated
  liquid inlet. Older versions returned a value without physical meaning. The
  viscosity of a two-phase pure fluid is now the McAdams viscosity of the
  homogeneous equilibrium model.
  See :py:func:`~tespy.tools.fluid_properties.functions.viscosity_mix_ph` for
  the model and its limitations
  (`PR #1093 <https://github.com/oemof/tespy/pull/1093>`__).

Other Changes
#############
- A singular Jacobian during no longer aborts the calculation immediately.
  Instead a dampened step (Levenberg-Marquardt) is performed
  (`PR #1094 <https://github.com/oemof/tespy/pull/1094>`__).
- Saved and exported data contain a :code:`meta` block (kind, format and tespy
  version, git commit, timestamp), which is checked on load for clear errors
  (`PR #1088 <https://github.com/oemof/tespy/pull/1088>`__).
- The unit handling of the data containers has been reworked: a value is stored
  together with its unit string and converted through the unit system of its
  network, a plain number is bound to the default units at the first solve.
  There is no module level unit registry any more, pint quantities of any
  registry are accepted and the unit conversions in the solver loop do not
  create pint objects. Visible changes: :code:`unit` of a plain specification
  is :code:`None` before the first solve, :code:`val0` is always a number and
  the new :code:`val0_with_unit` returns the starting value as quantity
  (`PR #1089 <https://github.com/oemof/tespy/pull/1089>`__).
- The :code:`tespy.tools.fluid_properties.wrappers` module has been split into
  a subpackage with one module per wrapper, imports remain unchanged
  (`PR #1067 <https://github.com/oemof/tespy/pull/1067>`__).

Documentation
#############
- Two new notebooks showcase the fluid property engines: a
  :ref:`comparison of the fluid property back ends <fluid_property_backends_label>`
  benchmarks CoolProp HEOS, REFPROP and thermopack, and a
  :ref:`how-to guide on zeotropic mixtures <zeotropic_heat_pump_label>`
  models a heat pump
  (`PR #1067 <https://github.com/oemof/tespy/pull/1067>`__).
- The heat exchanger component docstrings now specify the hot and cold side
  ports explicitly, and the connections overview documents the
  :code:`HAConnection` building block
  (`PR #1081 <https://github.com/oemof/tespy/pull/1081>`__,
  `PR #1082 <https://github.com/oemof/tespy/pull/1082>`__).
