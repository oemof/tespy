v0.12.0 - Under development
+++++++++++++++++++++++++++

API Changes
###########
- The data containers of components and connections have been restructured
  with clearly separated responsibilities. Every container answers two
  independent questions: what kind of value it stores and whether it can put
  an equation into the system. The former names stay available for one release
  and emit a :code:`FutureWarning`, they also recognise instances of their
  replacement in :code:`isinstance` checks
  (`PR #XXXX <https://github.com/oemof/tespy/pull/XXXX>`__):

  - :py:class:`~tespy.tools.data_containers.ConnectionParameter` replaces
    :code:`FluidProperties` and
    :py:class:`~tespy.tools.data_containers.ComponentParameter` replaces
    :code:`ComponentProperties`. Both are scalars with a physical quantity
    sharing the :py:class:`~tespy.tools.data_containers.ScalarParameter` base,
    the component parameter adds the :code:`"var"` switch, bounds scaling and
    result post-processing.
  - :py:class:`~tespy.tools.data_containers.ArrayParameter` replaces
    :code:`ComponentArrayProperties`. Arrays are the shape-valued sibling of
    the component parameter: they share the result flag :code:`is_result`,
    the :code:`calc` hooks and can carry an equation. :code:`result_only` is
    derived from :code:`is_result` and the presence of an equation.
  - :py:class:`~tespy.tools.data_containers.ConfigParameter` replaces
    :code:`SimpleDataContainer` for typed configuration values without unit
    and without equation. The declared :code:`dtype` is now validated.
  - :py:class:`~tespy.tools.data_containers.ParameterGroup` replaces
    :code:`GroupedComponentProperties`: an equation activated when all of
    its element parameters are specified.
    :py:class:`~tespy.tools.data_containers.OptionalEquation` replaces
    :code:`GroupedComponentCharacteristics` and the boolean equation switches
    held in simple containers before: an equation the user switches on, e.g.
    :code:`cone`, :code:`fluid_balance` or :code:`UA_char` of heat
    exchangers, whose :code:`elements` only name the parameters it reads.
  - :py:class:`~tespy.tools.data_containers.CharacteristicData` and
    :py:class:`~tespy.tools.data_containers.CharacteristicEquation` replace
    :code:`ComponentCharacteristics` and :code:`ComponentCharacteristicMaps`.
    The data container holds a characteristic that another equation reads,
    the equation container activates its own equation. The containers are
    blind to the representation of the characteristic and strict on its
    signature: any object with the declared number of inputs is accepted.
    Providing a characteristic to a data container marks it as specified,
    e.g. for the activation of a parameter group. Providing one to an
    equation container does not activate the equation, as before.
  - :py:class:`~tespy.tools.data_containers.MandatoryConstraint` replaces
    :code:`ComponentMandatoryConstraints` and
    :py:class:`~tespy.tools.data_containers.ReferenceEquation` replaces
    :code:`ReferencedFluidProperties`.

- Characteristic functions carry a physical quantity per axis. Components
  evaluate them through the container with SI inputs and receive SI outputs,
  the conversion to the units of the data is handled by the container.
  Dimensioned axes, e.g. the volumetric flow and the pressure rise of the
  :code:`flow_char` of a pump, follow the default units of the network like
  any other specification. Before, these data were SI data regardless of the
  network's units. A warning is raised where the interpretation changed, i.e.
  for dimensioned data without declared units in a network whose defaults
  are not SI. Check your data or declare their units with the
  :code:`input_units` and :code:`output_unit` keywords of the container, e.g.
  :code:`pump.set_attr(flow_char={"char_func": line, "input_units": ["m3/s"], "output_unit": "Pa"})`.
  The default characteristics shipped with tespy are SI data. Equations of
  custom components should call :code:`self.my_char.evaluate(x)` instead of
  :code:`self.my_char.char_func.evaluate(x)`.
- The new :py:class:`~tespy.tools.characteristics.Polynomial` and
  :py:class:`~tespy.tools.characteristics.EN12900Polynomial` are
  characteristic representations next to :code:`CharLine` and
  :code:`CharMap`. The :py:class:`~tespy.components.displacementmachinery.polynomial_compressor.PolynomialCompressor`
  takes its efficiency polynomials :code:`eta_s_poly` and :code:`eta_vol_poly`
  as :code:`EN12900Polynomial` objects, which are evaluated in °C as defined by
  the standard whatever the network's temperature unit is. Passing the
  coefficients as list is deprecated.
- The :code:`reference_state` dictionary of the
  :code:`PolynomialCompressor` is deprecated. The component only needs the
  :code:`swept_volume` (quantity :code:`volume`) from it, which is a regular
  component parameter now. The functions generating the efficiency
  polynomials from manufacturer data take the reference state as the keyword
  arguments :code:`T_sh`, :code:`T_sc`, :code:`frequency` and
  :code:`swept_volume`, the dictionary is deprecated there as well. With the
  keyword :code:`units` the functions read all plain numbers, the table and
  the reference state, in the given unit system, e.g. the one of the network
  the polynomials are used in. Create the unit system first, fit, then create
  the network with :code:`Network(units=units)`. Without :code:`units` the
  table temperatures are °C as defined by EN 12900 and all other values SI.
  Quantities carry their own unit in both cases. The
  :code:`EN12900Polynomial` carries the °C of its axes, so the containers
  read them without a declaration.
- The unit system knows the quantity :code:`volume` with default unit
  :code:`m3`.
- A scalar or array component parameter is an input when it carries an
  equation, is an element of a parameter group or can become a system
  variable. A parameter flagged :code:`is_result` without any of these is
  result-only and refuses user values with a :code:`TypeError` instead of
  silently ignoring them (:issue:`1070`). The :code:`result_only` property
  tells the state of a parameter.
- References of connection parameters to the same parameter of another
  connection are attached to the parameter: :code:`c.m.reference` holds the
  :py:class:`~tespy.tools.data_containers.ReferenceEquation`. The former
  sibling parameters :code:`m_ref`, :code:`p_ref`, :code:`h_ref`,
  :code:`T_ref` and :code:`v_ref` are gone from the parameter tables, the
  attributes stay available with a :code:`FutureWarning`. The energy flow
  :code:`E` of power and heat connections can be referenced now, e.g.
  :code:`e2.set_attr(E=Ref(e1, 0.5, 0))`. Saved files keep their format.
- The :code:`subcooling` switch of the
  :py:class:`~tespy.components.heat_exchangers.condenser.Condenser` is a
  configuration value. The saturated liquid outlet equation it disables is a
  mandatory constraint of the component now, which is left out when
  subcooling is allowed. The specification :code:`subcooling=True` is
  unchanged.
